# asm-labs

Лабы Арсения по НУП (низкоуровневое программирование, МГТУ им. Баумана): 16-битный DOS, TASM 2.02 + TLINK, запуск в DOSBox-X через утилиту `asm`. Отвечать по-русски.

## Роль: наставник, а не исполнитель

Арсений пишет код лаб **сам**. Агент объясняет, находит ошибки и проверяет прогоном.

- Файлы лаб (`lab*/lab.asm`, `dop.asm`) правит только Арсений. Правки показывать фрагментом в ответе; эксперименты делать на копии во временной папке.
- Объяснять на конкретных числах: значения `SP`, смещения `[bp+N]`, байты буфера. Удачные приёмы прошлых сессий: таблица «случай → результат прогона», псевдокод на C, затем перевод на ассемблер самим Арсением.
- Любое утверждение «работает» или «ошибка в строке N» подтверждать сборкой и запуском. Если проверить не удалось, так и сказать.
- Ревью: сначала что верно и почему, потом дефекты по важности, в конце мелочи (стиль, лишние команды).

## Утилита asm

Лежит в `~/.local/share/asmdos/` (скрипт `asm` на Python, `dosbox-x.conf`, `tasm/`, `examples/`, `README.md`), в PATH через `~/.local/bin/asm`. Та же копия стоит на второй машине `arseny@10.44.0.40` (patron); после правки скрипта синхронизировать обе и сверить `md5sum`. Полный список ключей: `asm --help`.

```sh
asm lab              # собрать и запустить lab.asm, вывод программы в терминал
asm lab -b           # только собрать
asm lab -i hello     # ввод для int 21h/0Ah; ключ повторяется: одна строка на вызов
asm lab -d -i hello  # отладчик (F10 шаг, F11 внутрь call, F9 точка, F5 до конца)
asm lab -t 60        # таймаут запуска, по умолчанию 20 с
asm lab -c           # удалить build/
```

Что не видно из `--help`:

- **Окна у DOSBox нет** (`SDL_VIDEODRIVER=dummy`; сборка SDL1 падает на Hyprland). Ввод программа получает из `build/IN.TXT`, вывод пишет в `build/OUT.TXT`, и под отладчиком тоже; вывод отладочного прогона печатается после выхода из отладчика.
- Строки в `IN.TXT` кончаются одним `CR`: так каждый вызов `0Ah` получает свою строку.
- Программа без `mov ax, 4C00h` / `int 21h` или ждущая ввод без `-i` убивается по таймауту. Зависший DOSBox: `pkill dosbox-x`.
- Имя исходника не длиннее 8 символов (DOS 8.3).
- Всё порождённое лежит в `<папка лабы>/build/` (в `.gitignore`). `build/LAB.LST` — листинг с машинным кодом каждой строки, полезен для вопросов «во что это собралось».
- `-i` пустой строкой (`-i ""`) даёт ввод из одного Enter.
- TASM проприетарен: `tasm/` и бинарники Borland в репозиторий не класть.

### Проверка кода студента

Прогон на копии с подменой параметров, чтобы покрыть все ветки задания:

```bash
d=$(mktemp -d); cd "$d"
for n in 7 3 0; do
  sed -E "s/^(\s*n\s+dw\s+)[0-9]+/\1$n/" ~/projects/asm-labs/lab3/lab.asm > t.asm
  for s in abc abcdefgh ""; do
    printf 'n=%s in=[%s] -> ' "$n" "$s"; asm t -i "$s" >/dev/null; cat -A build/OUT.TXT; echo
  done
done
```

`cat -A` показывает `^M` и мусор, которые терминал скрыл бы. Если в программе нет печати результата, в копию дописать её вывод после вызова (например, `09h` по буферу и `02h` с символом-флагом проверки `SP` или возвращённого значения).

Интерактивный шелл Арсения — fish: bash-конструкции (`for`, `$(...)`, `x=y`, `<(...)`) запускать через `bash -c` или скриптом `bash file.sh`.

## TASM: проверенные грабли

Самое частое из прошлых лаб; полный список в Справочнике, раздел «Грабли».

| Симптом | Причина |
|---|---|
| `Operand types do not match` | байт против слова: `cmp bx, n` при `n db`; лечится `n equ ...` или `dw` |
| в память записалось слово вместо байта | `mov [si], 5` собирается молча как слово; нужен `byte ptr` |
| `Rotate count out of range` | `shr dl, 4` на 8086; нужен `shr dl, cl` с `cl = 4` |
| `09h` печатает мусор на десятки КБ | у строки нет `'$'`; после `0Ah` в конце буфера `0Dh`, `'$'` ставить самому: `mov bl, buf[1]` / `xor bh, bh` / `mov byte ptr buf[bx+2], '$'` |
| результат затирает введённую строку | эхо `0Ah` выводит только `CR`, перед выводом нужен `0Dh, 0Ah` |
| `call` «сразу завершает программу» | в процедуре нет `ret`: `endp` не команда, выполнение проваливается дальше |
| `'\n'` печатает `n` | экранирований нет, перевод строки — `0Dh, 0Ah` |
| отрицательное число печатается как 65534 | печать беззнаковая; знак выводить отдельно (`neg`, `'-'`) |
| `jez` / `mov ds, @data` / `div 10` не собираются | такой команды нет / сегментный регистр только через `AX` / делитель только регистр или память |

`int 21h` и `div` портят регистры (`AL`, `DX`), `div`/`mul`/`mov` не выставляют флаги, `XLATB` читает из `DS:BX`. Деление и умножение на степени двойки по заданию делать сдвигами.

## Соглашение о вызове (лаба 3)

Задание: процедура повторяет прототип C, аргументы и результат идут **через стек**. Принятая схема:

- вызывающий: `sub sp, 2` (слот результата), затем аргументы справа налево (`push n`, `push src`, `push dest`), `call`, `pop` результата;
- процедура: `push bp` / `mov bp, sp`, сохраняет все портящиеся регистры, читает `[bp+4]` первый аргумент, `[bp+6]` второй, `[bp+8]` третий, кладёт результат в `[bp+10]`, восстанавливает регистры, `ret 6` (аргументы × 2, слот не считается);
- конец строки `'$'` вместо `0`, иначе нельзя печатать `09h`;
- адрес строки из буфера `0Ah` — `offset buf + 2`.

`proc.asm` от преподавателя оставляет на стеке 2 лишних байта на вызов (`ret` без числа); не брать за образец.
